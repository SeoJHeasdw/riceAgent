# RICE i18n 가이드 (핸드오프 스펙)

이 문서는 **화면/컴포넌트의 한글 하드코딩을 다국어 카탈로그로 옮기는 반복 작업**의 스펙이다.
뼈대는 이미 세워져 있고, 남은 건 73개 파일에 같은 패턴을 반복하는 일이다. 저렴한 툴/에이전트에
이 문서를 그대로 물려주면 된다.

레퍼런스 구현: [`src/screens/SettingsScreen.tsx`](../src/screens/SettingsScreen.tsx) — 아래 패턴이 실제로 적용된 예시.

---

## 1. 아키텍처 한눈에

- 라이브러리: **react-i18next** (i18next 26 / react-i18next 17)
- 카탈로그: **로케일별 × 네임스페이스별 JSON** — `src/locales/<lang>/<namespace>.json`
- **`ko` = 원본(source of truth)**, `en` = 번역 타깃, fallback = `ko` (en 키가 비면 자동으로 ko 표시)
- 키는 **타입 지정**됨 → `t('appearance.title')` 오타 시 컴파일 에러 + 자동완성 (`src/lib/i18n/react-i18next.d.ts`)
- 백엔드는 **자연어 문장을 만들지 않는다.** 에러는 안정적 `code`(+`params`)로 내려오고, 표시 문구는 프론트 `errors` 카탈로그가 담당.

```
src/
  locales/
    ko/  common  settings  chat  skills  plugins  errors  (.json)   ← 원본
    en/  common  settings  chat  skills  plugins  errors  (.json)   ← 번역
  lib/i18n/
    index.ts             i18next 초기화 (언어/네임스페이스 등록) — 단일 진입점
    react-i18next.d.ts   ko 기준 키 타입 증강
    I18nContext.tsx      useI18n() — 언어 읽기/전환 전용(문자열 X)
    apiError.ts          백엔드 에러코드 → 지역화 문구
i18next-parser.config.js 코드 스캔 → 카탈로그 동기화 도구 설정
```

## 2. 세 가지 사용 패턴

### (A) 컴포넌트 문자열 → `useTranslation`

```tsx
import { useTranslation } from 'react-i18next';

function Foo() {
  const { t } = useTranslation('settings');   // 네임스페이스 지정
  return <h1>{t('title')}</h1>;                 // settings.json 의 "title"
}
```

- 다른 네임스페이스 키가 필요하면 접두사로: `t('common:cancel')`
- 보간: `t('workspace.mkdir_failed', { detail })` ↔ 카탈로그 `"...: {{detail}}"`
- 복수형: `t('items', { count })` ↔ `"items_one"` / `"items_other"` (i18next 표준)

### (B) 언어 읽기 / 전환 → `useI18n`

```tsx
import { useI18n } from '../lib/i18n/I18nContext';

const { language, setLanguage } = useI18n();   // 'ko' | 'en'
setLanguage('en');                              // 저장 + 즉시 반영
```

문자열 번역은 여기서 하지 않는다. 언어 선택 다이얼로그·설정 화면처럼 "언어 자체"를 다룰 때만 사용.

### (C) 백엔드 에러 표시 → `apiErrorMessage`

```tsx
import { apiErrorMessage } from '../lib/i18n/apiError';

const res = await api.updateWorkspaceLocation(path);
if (!res.success) toast.error(apiErrorMessage(res));  // res.code + res.params 를 errors 카탈로그로 매핑
```

## 3. 화면 마이그레이션 절차 (한 파일 = 이 단계 반복)

1. **파일 안의 한글(및 대응 영어)을 모두 찾는다.**
   - JSX 텍스트: `<span>메시지를 입력하세요</span>`
   - 속성: `placeholder="검색..."`, `aria-label="닫기"`, `title=...`
   - **안티패턴 삼항**: `{language === 'ko' ? '저장 안 됨' : 'Unsaved'}` ← 반드시 카탈로그로 흡수
2. **네임스페이스를 고른다.** 화면 단위로: `chat`, `skills`, `plugins`, `connectors`, `home`, `onboarding` … (없으면 §5로 새로 만든다)
3. **키를 정한다.** 의미 기반 계층: `appearance.themeDark`, `sidebar.newChat`. UI 문구 자체를 키로 쓰지 말 것.
4. **`ko/<ns>.json` 에 한국어**, **`en/<ns>.json` 에 영어**를 같은 키로 넣는다.
   - 기존에 영어 대응이 이미 있으면(삼항 등) 그대로 en 에 옮긴다. 없으면 en 은 자연스러운 번역으로 채운다.
5. **코드를 치환한다.**
   - 상단에 `import { useTranslation } from 'react-i18next';`
   - 컴포넌트 안에 `const { t } = useTranslation('<ns>');`
   - `메시지를 입력하세요` → `{t('chat.placeholder')}` (또는 ns 지정 시 `t('placeholder')`)
   - 삼항 `language === 'ko' ? A : B` → `t('key')` (삼항 자체를 제거)
6. **타입체크**: `npm run type-check` — 키 오타/누락이 있으면 여기서 잡힌다.

### Before → After (SettingsScreen 실제 예)

```tsx
// Before
const { language, setLanguage, t } = useI18n();
<h1>{t.settings.title}</h1>
{language === 'ko' ? '저장 안 됨' : 'Unsaved'}

// After
const { language, setLanguage } = useI18n();
const { t } = useTranslation('settings');
<h1>{t('title')}</h1>
{t('unsaved')}
```

## 4. 번역하지 말 것 / 할 것

**하지 말 것**
- 언어명 라벨: `English`, `한국어` (각 언어 표기 그대로 둔다)
- 모델용 프롬프트(`rice-runtime/.../prompts/`): 모델이 대화 언어를 따라가므로 번역 대상 아님
- 코드 주석, 로그, 개발자용 에러 dev-message
- 고유명사/브랜드: `RICE`, `Ollama`, `Claude`, URL, 코드 식별자

**할 것**
- 사용자 눈에 보이는 모든 UI 텍스트: 버튼/라벨/플레이스홀더/aria-label/title/toast/빈상태 문구
- 백엔드 에러의 **표시 문구**(코드→카탈로그 매핑, §6)

## 5. 새 네임스페이스 추가

1. `src/locales/ko/<ns>.json` + `src/locales/en/<ns>.json` 생성
2. [`src/lib/i18n/index.ts`](../src/lib/i18n/index.ts):
   - 상단에 `import ko<Ns> from '../../locales/ko/<ns>.json';` (en 도)
   - `NAMESPACES` 배열에 `'<ns>'` 추가
   - `resources.ko`/`resources.en` 에 `<ns>: ko<Ns>` 등록
3. [`src/lib/i18n/react-i18next.d.ts`](../src/lib/i18n/react-i18next.d.ts): `import type <ns> ...` + `resources` 에 `<ns>: typeof <ns>` 추가

## 6. 새 언어 추가 (예: 일본어 `ja`)

1. `src/locales/ja/` 폴더에 **모든 네임스페이스 JSON**을 `ko` 와 같은 키로 채운다
2. [`src/lib/i18n/index.ts`](../src/lib/i18n/index.ts):
   - `SUPPORTED_LANGUAGES` 에 `'ja'` 추가
   - `ja` 네임스페이스 import + `resources.ja` 등록
3. 언어 선택 UI([`LanguageSelectDialog.tsx`](../src/components/carbon/LanguageSelectDialog.tsx), 설정 화면)의 언어 목록에 항목 추가

키 구조가 `ko` 와 동일하기만 하면 나머지는 자동으로 동작한다.

## 7. 추출 도구 (선택)

```bash
npm run i18n:extract
```

코드의 `t('...')` 호출을 스캔해 카탈로그에 **누락 키를 추가**한다(`keepRemoved: true` 라 삭제는 안 함).
설정: [`i18next-parser.config.js`](../i18next-parser.config.js). 첫 실행 시 `sort: true` 로 키가 알파벳순 정렬된다.

> `errors` 네임스페이스는 백엔드 코드를 반영하는 **수동 카탈로그**다(§6). 파서가 동적 조회 키를 못 잡으니 손으로 맞춘다.

## 8. 백엔드 에러코드 계약

런타임은 사용자 문장을 만들지 않는다. 에러는 이렇게 내려온다:

```json
{ "success": false, "error": "<dev fallback>", "code": "workspace.path_not_absolute", "params": { "detail": "..." } }
```

- 백엔드에서 새 에러를 던질 때: 한글 문장 대신 **안정적 `code` + 보간용 `params`**를 준다.
  ```python
  raise ValidationError("workspace path must be absolute", code="workspace.path_not_absolute")
  raise ValidationError("failed to create dir", code="workspace.mkdir_failed", params={"detail": str(exc)})
  ```
  (`RiceError` 계열: `core/errors.py`. 통합 핸들러가 `code`/`params`를 봉투에 실어 보낸다.)
- 프론트: 그 `code` 를 `src/locales/<lang>/errors.json` 에 등록하고, 표시할 때 `apiErrorMessage(res)` 사용.
- 두 곳(백엔드 코드 ↔ `errors.json` 키)이 짝을 이뤄야 한다.
